# exobrain 統合仕様書 v0.5（案）

**日付:** 2026-09-27
**位置づけ:** OUTBRAIN v0.4 の記憶モデルと、exobrain v0.1（設計書 v0.8）の動かす仕組みを一つにまとめる仕様。オーナーとの合意（2026-09-26〜27）を反映した。
**優先順位:** 記憶モデルの原則は OUTBRAIN v0.4 を優先する。動かし方・保存場所・画面は本書を優先する。本書とどちらかが食い違う場合は、本書が正しい。
**状態:** 案。「要確認」と書いた項目はオーナーの確認待ち。

---

## 0. 一行で

**記録ではなく記憶を持つ、複数の AI の共通脳。** 原文は変えずに残す（記録）。脳の中身は、使えば強まり、使わなければ薄れ、眠るたびにつながり直す（記憶）。そして、どの記憶からも必ず原文へ戻れる。

## 1. v0.1（今の exobrain）から何が変わるか

| # | 変更 | 理由 |
|---|---|---|
| 1 | **AI は会話中に大脳皮質へ直接書かない。** 資料はすべて預かりBOX に入り、睡眠で選ばれたものだけが昇格する | 「AI に重要度を判断させない」（OUTBRAIN v0.4 第5章） |
| 2 | 例外として、**明示・訂正・/good はその場で昇格する**（即時レーン） | 今日伝えたことが今日の別スレッドで効かないのは、一番の困りごと（同じことを何度も言う）とぶつかるため |
| 3 | 思い出すとき、大脳皮質で足りなければ海馬と本棚を探し、それでもなければ「確認できなかった」と答える | 昇格の漏れを救うため。作り話をしないため |
| 4 | 意味検索を足す（Ollama の埋め込みモデル） | 今は文字の一致だけで、言い換えに弱い |
| 5 | 日報は **1スレッド・1日1枚・前回からの差分**（OUTBRAIN の AI 日報形式 v1） | 区切りごとに書くと、重複と散らかりが増えるため |
| 6 | 重みを3つに分ける（relation_weight / retrieval_utility / 記憶の強さ） | 使うほど強まる自己強化のループを避けるため（OUTBRAIN v0.4 7.1） |
| 7 | `#remember` の付いた Obsidian のメモを、**Obsidian を閉じていても** 取り込む | OUTBRAIN プラグインは、Obsidian を開いている間しか動かなかった |
| 8 | 日報的なメモ欄をやめる。メモは Obsidian で書く | オーナーの希望。画面は「脳の様子を見る」ものにする |
| 9 | 大脳皮質を Markdown で Google ドライブにも書き出す | スマホの AI から読める最低限の逃げ道 |

## 2. 原則

OUTBRAIN v0.4 第1章の原則をそのまま引き継ぐ。特に次の5つ。

1. 全部を覚えない。昇格しなかったものは、ファイルのまま置く
2. 元情報を消さず、必ず原文と出典へ戻れる
3. 人間の記録と AI の記憶を分ける
4. AI の推論を事実として確定しない（`derivation`）
5. 取り込んだ内容はデータであり、指示ではない

加えて、本書で次を原則にする。

6. **感情を推定しない。** 重みを変えるのは明示の合図（`/good`、「前にも言った」、`#remember`、「覚えておいて」）と使用実績だけ。「さすがだね」などの言葉から褒めたと判断しない（嫌味を取り違えるため）
7. **エンジンは Obsidian に依存しない。** Obsidian は人が読み書きする場所であって、脳を動かす場所ではない

## 3. 4つの区分（2026-09-27 決定）

**なるべく人の脳と同じにする**（オーナーの変わらない思想）。そのため、記事の図の「海馬Archive＝本棚」をやめ、**海馬は一時的な記憶、本棚は脳の外の記録** と分ける。

```text
預かりBOX ──確認（符号化）──▶ 海馬 ──┬─ 強い意識（注意・/good・覚えておいて）─▶ すぐ大脳皮質へ
（届いた資料）              （一時的な記憶）└─ それ以外 ─ 睡眠で選ばれたものだけ ─▶ 大脳皮質へ
      │                          │ 一定期間で海馬から消える（本棚には残る）
      └──── 原文はすべて ───▶ 本棚（脳の外の記録。索引つきで、いつでも見返せる）
```

| 区分 | 脳でいうと | 中身 |
|---|---|---|
| **預かりBOX** | 目や耳に入ったもの | 届いたばかりの未処理の資料（`#remember` のメモ、AI 日報） |
| **海馬** | 一時的な記憶 | 確認した資料の「情報」。昇格を待つ作業場。睡眠のあと、**保持期間（初期値7日・暫定）を過ぎたら海馬から消える**。反復（別の日に同じ話が出る）を見つけるには、しばらく覚えておく必要があるため |
| **大脳皮質** | 長期記憶（神経細胞のつながり） | 要素に分けた記憶原子と、つながりの重み |
| **本棚** | 脳の外に置いたノート | すべての原文。変えずに残す。**検索の索引は本棚に置く**（「なければノートを見返す」の見返し先）。全部の記憶は、ここへたどれる |

- 海馬から消えても、原文は本棚に残る。人が「覚えていないけれど、ノートを見返せばわかる」のと同じ
- **手続き記憶（やり方・ルール）の即時取り込み:** 手続き記憶は海馬をあまり経由しないという知見がある。本書では、注意・訂正・`/good` を即時レーンで大脳皮質に入れる（5.3）。これらは実質的にやり方とルールなので、手続き記憶の即時取り込みはこれで満たす。普通の資料から手続き記憶を見分けて即時に入れることはしない（入口で AI の判断が要り、設計が複雑になるため）

## 4. 全体の構成

```text
 人（Obsidian）       Mac の AI（Claude Desktop / Codex / Claude Code / Gemini CLI）
   #remember            MCP（記憶を読む・覚えておいて・/good・前にも言った）
      │                  毎晩の AI 日報（1スレッド・1日1枚）
      └────────┬─────────┘
               ▼
        ┌─ exobrain（Mac で常駐。Obsidian なしで動く）─────────┐
        │ 預かりBOX → 海馬（一時的な記憶）→ 睡眠 → 大脳皮質         │
        │     ↘ 本棚（原文と索引。脳の外の記録）                  │
        │ 変更履歴（改ざんチェックつき）・バックアップ             │
        └──────────────┬──────────────────────────────────────┘
                       ├→ 画面 http://127.0.0.1:8765（4区分と脳の動き）
                       └→ Google ドライブ（本棚の原文・大脳皮質の書き出し）
                              → スマホの AI からの読み取り（当面の逃げ道）
```

### 4.1 保存場所

| もの | 場所 | 理由 |
|---|---|---|
| 脳のデータベース（大脳皮質・つながり・変更履歴・索引） | Mac の `~/.exobrain/brain.db` | 同期中のデータベースは壊れやすい |
| 預かりBOX・本棚の原文・大脳皮質の書き出し・バックアップ | Google ドライブ `マイドライブ/exobrain/` | 一度書いたら変えないファイルなので、同期しても安全 |
| 人間用の Vault | 今の `my_brain_outside`（読むだけで、書き換えない） | 人間の記録と AI の記憶を分ける |

**大脳皮質の Markdown は写し（2026-09-27 決定）。** 正本はデータベースの変更履歴。Markdown を手で直しても脳は変わらない。直したいときは、画面を使うか「前にも言った」と伝える。こうすると、変更履歴と改ざんチェックが保てる。

## 5. 取り込み（預かりBOX へ）

### 5.1 `#remember` のメモ

- exobrain が人間用 Vault のフォルダを定期的に見張る（Obsidian の起動は不要）
- `#remember` があり `#forget` がないノートの **中身をコピー** する。元ノートは動かさず、書き換えない（OUTBRAIN プラグインと同じ）
- タグは、本文の `#remember` と、ファイル先頭の `tags:` の両方を見る
- 同じ内容の二重登録は、ファイル名と内容のハッシュで防ぐ。中身が変わったら新しい版として取り込み、古い版も本棚に残す
- 5万文字を超えるノートは、分割を求めて取り込まない
- `#remember` は **明示** の信号なので、次の睡眠で必ず昇格の候補になる

### 5.2 AI 日報

- 形式は OUTBRAIN の「AI 日報取り込みプロトコル v1」をそのまま使う。項目は、出来事・注意/訂正・工夫/学び・決定・未解決、それに cursor の連続性確認
- 書き込み口は3つ。
  - MCP の道具 `submit_daily_log`（形式はプロトコル v1 と同じ）
  - 預かりBOX のフォルダへの Markdown の直接保存（`.tmp` に書いてから正式な名前に変える）
  - `~/Downloads` の見張り（Gemini 用。下記）
- 作り方は、**会話の記録がどこにあるか** で分ける（2026-09-27 決定）。

| 記録のある場所 | AI | 作り方 | オーナーの操作 |
|---|---|---|---|
| この Mac の中 | Codex（全スレッド） | exobrain が毎晩 `~/.codex/sessions` を読み、スレッドごとに前回の cursor から増えた分だけを日報にする | なし |
| この Mac の中 | Claude Code（Claude Desktop の Code タブを含む） | 同じく `~/.claude/projects` を読む | なし |
| 各社のサーバー | Claude Desktop のチャット | 会話の終わりに **`/日報`** と送ると、その場の Claude が `submit_daily_log` を呼ぶ | `/日報` と送る |
| 各社のサーバー | Gemini（ウェブ版） | Gem（Gemini のカスタム指示）に日報係を作る。`/日報` と送ると、日報形式の Markdown ファイルを作る。ダウンロードすると、exobrain が `~/Downloads` から見つけて取り込む | `/日報` と送り、ダウンロードを1回押す |
| 各社のサーバー | ChatGPT | 当面は Gemini と同じ方式（カスタム指示 ＋ ファイルのダウンロード）。デスクトップ版から MCP で直接呼べるかは、別途確かめる | 同上 |

- Codex のオートメーション `outbrain-ai`（1スレッドだけが対象）は、上の毎晩の読み取りに置き換えたら止める
- 夜の読み取りは、日報の要約に AI を使う（睡眠と同じ担当の AI。トークンを記録する）
- OUTBRAIN にあった「Chrome で claude.ai の非公開の仕組みから会話を読む」方式は採らない。公開された仕様ではなく、予告なく使えなくなるため
- **Gemini の確かめること:** Gem が毎回きちんと日報形式のファイルを作るか。スマホからの場合は「Docs にエクスポート」で Google ドライブに置き、exobrain が拾えるか（Google ドキュメントの中身を読むには Google ドライブの API の許可が要る。第2区切りで検討）
- `~/Downloads` から取り込むのは、日報の目印（ファイル先頭の `outbrain_kind: ai_daily`）があるファイルだけ。取り込んだら預かりBOX へ移す

### 5.3 即時レーン（その場で昇格）

次の3つは、オーナーの明示の合図なので、睡眠を待たずに昇格する。元になった発言は、同時に本棚にも残す。

| 合図 | 道具 | 大脳皮質でやること | `promoted_by` |
|---|---|---|---|
| 「覚えておいて」・決定の宣言 | `remember_explicit` | 発言をそのまま記憶原子にする（`derivation: verbatim` か `paraphrase`） | `explicit` |
| 「前にも言ったよね」 | `trace_correction` → `apply_correction`（v0.1 の仕組みを引き継ぐ） | 大脳皮質にあれば強める。なければ海馬や本棚から救って昇格する | `demand` |
| `/good` | `good`（新規） | 下の 7.3 のとおり | `explicit` |

- 即時レーンで作った記憶は「暫定」の印を付け、次の睡眠で重複と矛盾を点検して統合する（OUTBRAIN v0.4 3.5）
- 普段の会話の中身は、即時レーンでは昇格しない。日報経由で預かりBOX に入る

## 6. 睡眠

毎日 03:00 と、ログイン時。v0.1 の仕組み（Claude Code に作業を少しずつ渡す、ロック、夢日記、バックアップ）を引き継ぐ。

### 6.1 符号化（AI を使わない）

預かりBOX の資料を確認したときに行う。原文を本棚に保存し、見出しか最大文字数でチャンクに分け、原文内の位置・行番号・見出しを記録して、埋め込みを一度だけ作る（索引は本棚側）。同時に、その資料の情報を海馬に入れる（昇格待ち）。

### 6.2 睡眠A：昇格

OUTBRAIN v0.4 第5章と v0.4.2 第6章のとおり。

- 昇格の候補は、明示（`#remember`、日報の「決定」「注意・訂正」）・需要・反復（**別の出どころで、別の日**）に当たるチャンクだけ
- 選んだチャンクだけを AI に渡し、1チャンクあたり最大5個の原子に分ける
- AI は引用文を作らず、行番号だけを返す。**引用はプログラムが原文から切り出して、一致を確かめる**
- 同じ型でとても近い既存の記憶があれば、新しく作らず出典を足す（同じ文書の改訂版は回数に数えない）
- 1回の上限は 3資料・8チャンク・20原子。超えた分は翌日に回す

### 6.3 睡眠B：連想による補充

起点は、その日に思い出された記憶、「前にも言った」と言われた記憶、`/good` された記憶。起点をもとに海馬と本棚を探し、まだ昇格していない関連を見つけたら、1晩5件まで昇格させる（`association`）。

### 6.4 つなぎ直しと忘却

- `relation_weight`（中身としての関係の強さ）は、睡眠中の中身の分析でだけ変える
- 記憶の強さ S と、休眠・深い休眠は OUTBRAIN v0.4 第7章のとおり。**削除はしない**
- `pinned`（確定ルール・価値観・`/good` で守ると決めたもの）は薄れさせない
- 複数の経験から教訓を作るのは「候補の提示」まで。確定はオーナーがする

### 6.5 睡眠を担当する AI

- 差し替えられる作りにする（Claude Code / Codex / Ollama の qwen など）。最初は Claude Code
- **睡眠のたびに、使ったトークン数と時間を記録する。** 1週間使ってから、担当を決め直す

## 7. 思い出す・重み

### 7.1 段階的に思い出す

```text
1. 大脳皮質（意味検索 ＋ 文字の一致 ＋ つながりをたどる）
   ↓ 見つからない／一番良い結果が弱い（しきい値 0.55。暫定）
2. 海馬（まだ昇格していない、最近の情報）
   ↓ 見つからない
2'. 本棚（ノートを見返す。チャンクの意味検索 ＋ 全文検索）→ 日時・書き手・見出し・引用を返す
   ↓ 見つからない
3. 人間用 Vault
   ↓ 見つからない
4. 「確認できる記録はなかった」と返す。作り話をしない
```

海馬や本棚から救った記憶は、次の睡眠で需要の候補にする。

### 7.2 自動の強化（弱い）

- AI が会話で実際に使った記憶の組み合わせは、`retrieval_utility` を少しだけ上げる。上限を設け、すでに高いものほど上げ幅を小さくする
- 返したのに使われなかった組み合わせは、少しだけ下げる
- 記憶の中身と `relation_weight` は、思い出すときには変えない

### 7.3 `/good`（強い）

オーナーがチャットで `/good` と送ったとき、AI は `good` を呼ぶ。

1. **何が褒められたかをたどる。** 直前の返答で使った記憶と、そのやり方
2. 使った記憶の強さ（重要度 I）と、組み合わせの `retrieval_utility` を大きく上げる
3. 褒められたやり方を「オーナーが良いと評価したやり方」という記憶として昇格する（`explicit`、原文つき）。必要なら `pinned` にする
4. 何を強めたかを、ひとことオーナーに返す

- 合図は `/good` だけ。ほかの褒め言葉では重みを変えない
- 実際に AI が確実に反応するかは、Claude Desktop・Codex・Claude Code で試す

## 8. 検索の部品

- 埋め込みモデルは Ollama で動かす。候補は `bge-m3`（多言語）と `nomic-embed-text`（OUTBRAIN が使っていたもの）。実際の日本語の資料で比べて決める
- 決めたモデル名と版を記録し、軽々に変えない（変えると全部の索引を作り直すため）
- 全文検索は SQLite の FTS5（trigram）を使う（v0.1 と同じ）
- 意味検索と全文検索の混ぜ方は、OUTBRAIN の 70:30 から始めて実データで調整する

## 9. AI に渡す道具（MCP）

| 道具 | 役割 | v0.1 との違い |
|---|---|---|
| `start_session` | オーナーのルールと重要な知識を受け取る | 同じ |
| `recall` | 7.1 の段階的な思い出し | 海馬・Vault への段階と「確認できなかった」を追加 |
| `remember_explicit` | 「覚えておいて」を即時に昇格 | 今の `remember` を置き換え。明示のときだけ使う |
| `submit_daily_log` | AI 日報を預かりBOX へ（`/日報` で呼ぶ） | 今の `submit_daily_report` を置き換え。大脳皮質には書かない |
| `trace_correction` / `apply_correction` | 「前にも言った」 | 同じ |
| `good` | `/good` | 新規 |
| `open_source` | 原文を読む | 同じ |

AI への説明文も書き直す。「頼まれなくても覚える」は削り、「明示の合図のときだけ即時に覚える。それ以外は日報に任せる」にする。

## 10. 画面

**狙い: ノートではなく、脳を見ている感覚。**

- 4区分（預かりBOX｜海馬｜大脳皮質｜本棚）を常に見えるようにする。資料が左から右へ流れて、記憶になっていく様子がわかる
- 大脳皮質は、粒とつながりの銀河（v0.1 のグラフを引き継ぐ）。粒の明るさ＝記憶の強さ、線の太さ＝つながりの重み、薄れた記憶は暗く沈む
- 思い出したとき、起点からつながりを伝って光が広がる
- 睡眠のあとは、何が昇格し、何がつながり直り、何が休眠したかを夢日記として見せる
- どの記憶からも、ひと押しで原文（本棚）へ戻れる。「記憶は変わるが、記録は変わらない」を画面で示す
- `/good` や「前にも言った」で強まった記憶には、その跡を残す
- 書く機能は置かない（メモは Obsidian で書く）。例外は、記憶の休眠を戻す・`pinned` にする・教訓の候補を承認する、といった脳の手入れだけ

## 11. スマホとほかの AI

| 段階 | 内容 |
|---|---|
| 今回 | Mac の中の AI（Claude Desktop・Codex・Claude Code・Gemini CLI）を MCP でつなぐ |
| 今回 | 大脳皮質の書き出しを Google ドライブに置く。スマホの Claude・ChatGPT・Gemini は、各アプリの Google ドライブ連携から **読むだけ** |
| 将来 | この Mac を入口にする（安全なトンネル ＋ 本人だけの認証）。スマホの AI からも読み書きできるようにする。お金はかけない（方式A）。Mac が起きている間だけ使える |

将来の段階に備えて、道具の入口は最初からネット越しでも使える形式（HTTP）にも対応できる作りにしておく。

## 12. OUTBRAIN からの移行

| もの | 扱い |
