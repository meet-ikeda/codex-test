## 0. 本棚は保険（全体の前提）

脳（大脳皮質・つながり）は実験してよい層、本棚は壊さない層。この2層に分ける。

| 層 | 性格 | 壊れたら |
|---|---|---|
| 本棚（Google ドライブの Markdown） | 変えない・整理されている・exobrain がなくても読める | 起きてはいけない |
| 脳（`brain.db`） | 判断役が重みを変え、忘れ、つなぎ直す | 本棚から覚え直せばよい |

そのため、忘却（4章）や判断役（1章）を積極的に入れる前に、本棚の整理（8章）を先に仕上げる。

## 1. 誰が何を決めるか

v0.6 は「AI に重要度を判断させない」（v0.6 1章・2章の原則6、6.2、6.4）としていた。これを改め、判断を3者で分担する。

| 決める者 | 決めてよいこと | 決めてはいけないこと |
|---|---|---|
| **オーナー** | すべて。特に `pinned`（守るルール）、消去、教訓の確定の取り消し | – |
| **プログラム**（AI なし） | 反復・使用実績・時間による強弱、休眠、つながりの縮小と刈り込み（3章） | 中身の良し悪し |
| **判断役（Jev の枠）** | 昇格するか（重要度）、つながりを作る・強める・弱める、矛盾の判定と書き換えの提案、話題の種類の食い違い、教訓の確定（暫定の印つき） | `pinned` の付け外し、消去、オーナーの明示の合図より強い重みを付けること、原文の変更 |

判断役の決定には、必ず次を付ける。付いていない決定は受け付けない。

- 判断した AI の名前と版、理由（1〜2文）、根拠（本棚の原文の行番号か、記憶の id）
- 変更履歴に `actor: judge:<名前>` として残る。夢日記に「判断役が決めたこと」として一覧で出る
- 画面から1件ずつ取り消せる（取り消しも変更履歴に残る）
- 1晩の上限（昇格 20 原子・つながりの変更 100 本。暫定）

**変えないこと:** 褒め言葉や口調から感情を推定して重みを変えることはしない（嫌味の取り違えを防ぐ。v0.6 原則6のこの部分は残す）。判断役が見るのは中身と根拠だけ。

## 2. 判断役（Jev）の置き場所

### 2.1 Jev とは（2026-09-30 調べ）

- TypeSafe AI の最初の公開モデル（2026年9月発表）。文章を書かず、「状態」と「範囲の決まった問い」を受け取って、決定と確率を返す（出典: https://you.com/resources/what-is-jev 、https://www.explainx.ai/blog/typesafe-ai-jev-system-one-models-launch-2026 ）
- 呼び方の例: Python の `typesafe-sdk` で `TypeSafeClient(model="jev-1.13.0")`、`system_one(state=..., questions=...)`。問いの型 `noul` は 0〜1 の確率を返す（出典: https://www.honeyhive.ai/blog/how-to-use-typesafe-ais-jev-as-an-llm-judge ）
- 提供状況: 早期アクセス（待機リストから順に API キーを発行）。料金は入力100万トークンあたり 0.042 ドル、出力は無料（出典: 上記 you.com）
- 使い方の型:「自信があれば採る、自信がなければ推論できる AI に回す」（論文: https://arxiv.org/abs/2609.26550 。本文は未読）
- **確認できていないこと:** 日本語での精度、1回に渡せる量、待機リストの期間

### 2.1.1 無料の代わり: Kev（2026-09-30 調べ）

- Jev と同じ作り方の、無料で公開されたモデル。Qwen3.5 をもとにした 0.8B・4B・9B の3種類。Apache-2.0（出典: https://github.com/mobailabs/kev ）
- Mac（Apple Silicon）で MLX を使って動く。4B と 9B は 32GB の Mac に載る（同上）
- **Jev と同じ形の API**（`POST /v1/systemone`、`state` と `questions`、問いの型 `noul`・`choice`・`score`）。exobrain は同じ呼び方で Jev と Kev を差し替えられる
- 精度: 公開元の測定で、新しい出どころの資料に対して Kev-9B 0.837、Jev 0.857（同上）
- 注意点（公開元の記載）: 新しい分野では確率が当てにならないことがある（確信度 0.9 以上で 8.2% 誤り）、選択肢の順番で答えが変わることがある、学習した状態の長さは 384 トークンまで
- **確認できていないこと:** 日本語での精度、オーナーの MacBook Air のメモリで動く大きさ

**もう一つの候補: Jeff（2026-09-30 調べ）**

- Qwen3.5・Gemma 4 をもとにした 0.8B・2B の判断モデル。重みは Apache-2.0、コードは MIT。Jev と同じ形の API（`/v1/systemone`）。Mac は MLX で動く（出典: https://github.com/firelex/jeff ）
- 重みの大きさ: 0.8B が 1.7GB、2B が 4.2GB。M4 Max で1回 28ms（0.8B）・60ms（2B）（同上）
- 公開元の測定（5つの英語ベンチマーク）: Jeff-2B 83.1%、Jev 83.0%、Jeff-0.8B 79.1%（出典: 同上と https://github.com/firelex/jeff の要約記事）
- **公開元が「English and text only」と明記している。** 日本語は対象外
- 初期設定のポートが 8765 で、exobrain の画面と重なる。使うときは別のポートにする

**選び方:** Kev・Jeff とも Jev と同じ形で呼べるので、判断役の部品を一つ作れば両方を試せる。日本語の資料で測って決める（Kev-4B を先に試す。Jeff は英語のみと明記されているため2番手）。

**方針:** 判断役の呼び出しは System One の形（`state`・`questions`）にそろえ、Jev・Kev・Claude Code（代わり）を設定で切り替えられるようにする。Kev を先に試し、評価質問セットの資料で日本語の精度を確かめてから本採用する。

### 2.2 exobrain での役割分担

| 役 | 担当 | すること |
|---|---|---|
| 提案役 | Claude Code（今のまま） | 原文から記憶原子を作る、書き換え文を作る、理由を書く |
| 判断役 | **Jev** | 範囲の決まった問いに確率で答える（下表） |
| 迷ったときの判断役 | Claude Code（判断役用の別の指示） | Jev の確率が中間（例: 0.3〜0.7。暫定）のときだけ判断する |

Jev に聞く問い（どれも「はい/いいえ」か「どれか1つ」で答えられる形にする）。

| 問い | 型 | 使いどころ |
|---|---|---|
| この記憶原子は、オーナーの今後の仕事に役立つか | 確率 | 昇格（3.1 の判断役の重要度） |
| この2つの話題は同じものか | 確率 | 別名の統合、話題の重複 |
| 新しい記憶は、古い記憶と食い違うか | 確率 | 睡眠での見直し（5章） |
| この話題の種類はどれか（人／会社・組織／案件／道具・サービス／場所／話題） | 選択 | 種類の食い違い（v0.6 追記） |
| 提案役が出した記憶原子は、引用した原文で裏づけられるか | 確率 | 作り話の防止 |

- Jev は文章を書かないので、判断の記録には「問い・確率・提案役の理由」を残す
- **Jev に送らないもの:** `#機密` の資料と、そこから生まれた記憶（外部のサービスに送るため）
- API キーが手に入るまで、または Jev が使えないときは、迷ったときの判断役（Claude Code）がすべてを判断する。どちらを使ったかは記録に残る
- 判断役にかかった費用・時間・確率の分布を、睡眠ごとに記録する。1〜2週間使ってから、しきい値を決め直す

## 3. つながりの強さ

### 3.1 強める信号（v0.6 に追加）

| 信号 | 強さ | 決める者 |
|---|---|---|
| オーナーの明示（覚えておいて・前にも言った・`/good`・`#remember`・`> ` の発言） | 最も強い | オーナー |
| 反復（別の日・別の出どころ） | 強い | プログラム |
| 使用実績（一緒に思い出され、会話で使われた） | 弱い・上限あり | プログラム |
| **判断役の重要度判定** | 中（明示より下） | 判断役（新規） |

### 3.2 つながりの根拠

- つながりごとに、根拠になった資料と記憶の一覧を持たせる（今は出どころの種類 `origin` だけ）
- 画面で「なぜこの2つがつながっているか」を原文つきで示せる
- 原文を消去したとき、それだけを根拠にしていたつながりも一緒に消える

### 3.3 睡眠ごとの縮小と刈り込み

- 睡眠のたびに、`pinned` 以外のつながりの重みを全体で同じ割合だけ縮める（強いつながりは残り、弱いものほど相対的に薄れる。シナプス恒常性仮説の考え方）
- 縮めた結果、しきい値を下回ったつながりは外す。つながりは睡眠でいつでも作り直せるため
- 縮める割合としきい値は、まず「一部の記憶に想起が偏っていないか」を測ってから決める（暫定値は置かない）

## 4. 忘却と覚え直し

v0.6 6.4「削除はしない」を改める。**本棚から覚え直せる記憶は、忘れてよい。**

### 4.1 忘れてよい記憶

次をすべて満たす記憶原子だけ。

1. 本棚の原文への出典がある（覚え直せる）
2. `pinned` でも、オーナーの明示の合図で作られたものでもない
3. 長く使われず（休眠よりさらに長い期間）、強さがしきい値を下回った

### 4.2 忘れるとは

- 大脳皮質から外れる。思い出しの対象にも、グラフにも出ない
- 変更履歴には「忘れた」という出来事として残る（消去ではない）。原文は本棚に残る
- 消去（安全装置）とは別物。消去は今までどおりオーナーだけができる

### 4.3 覚え直し

- 思い出しの段階 2'（本棚）で見つかったものは、次の睡眠で昇格の候補になる（v0.6 7.1 のまま）
- **忘れた記憶と同じ出典から覚え直したときは、前の id を生き返らせ、前のつながりを弱めた状態で戻す。** 一度覚えたことは、二度目のほうが早く身につく（再学習の節約）
- 覚え直した記憶は、忘れにくくする（次に忘れるまでの期間を延ばす）

## 5. 睡眠での見直し（インターリーブ再生）

- 新しい資料から記憶を作るとき、判断役には「とても近い既存の記憶」（v0.6 6.2）に加えて、**関連する古い記憶を数件と、無作為に選んだ古い記憶を少し** 一緒に見せる
- 目的: 新旧の矛盾（決定が覆った、好みが変わった）に気づく。複数の経験に共通するやり方を見つける
- 矛盾を見つけたら、判断役が根拠つきで書き換え（v0.6 7.4 の再固定化）か、置き換え（`supersedes`）を決める

## 6. 思い出し方の比較

- 今の広げ方（3ホップまで、1ホップごとに半分、つながりの多い点で割り引く）と、Personalized PageRank（HippoRAG の方式）を、評価質問セット v2（`docs/eval-questions-v2.md`）で比べる
- 良かったほうを採る。差がなければ今のままにする
- 出典: HippoRAG（https://arxiv.org/abs/2405.14831 ）、HippoRAG 2（https://arxiv.org/abs/2502.14802 ）

## 8. 本棚の整理（Obsidian の世界観）

**狙い:** exobrain が止まっても、本棚だけで「探せる・読める・たどれる」。Obsidian でそのまま開けば、目次・リンク・グラフが働く。スマホの AI が Google ドライブ経由で読んでも迷わない。

### 8.1 変えないものと、作り直すもの

- **原文**（`本棚/原文/年/月/`）は一度書いたら変えない（今のまま）
- 整理のためのファイル（目次・話題のノート・月のまとめ）は、睡眠のたびにプログラムが作り直す。**写し** であることを先頭に書く。手で直しても次の睡眠で上書きされる（直したいことは Obsidian のメモとして書けば、預かりBOX から入る）

### 8.2 書式をそろえる

- すべての原文の先頭に、同じ項目の front matter: `種類`（AI日報・メモ・預け入れ・取材・クライアント）、`日付`、`書き手`（オーナー／AI の名前）、`スレッド`、`話題`（`[[名前]]` の一覧）、`tags`
- AI 日報の本文は、決まった見出しの順番（出来事・注意/訂正・工夫/学び・決定・未解決。今のプロトコル v1）。見出しの名前を変えない
- ファイル名は `日付_種類_書き手_題名.md`。並べるだけで時系列になる

### 8.3 話題のノート（Obsidian の「リンク先」）

- 日報やメモの `[[名前]]` ごとに、`本棚/話題/<名前>.md` を1枚作る。**これで、原文の `[[ ]]` が Obsidian で実際のリンクになり、グラフとバックリンクが働く**
- 中身: 種類（人・会社など）、別名、登場した資料の一覧（日付・書き手・その箇所の抜粋）、関係の深い話題、exobrain が覚えている要点（大脳皮質の写しへのリンク）
- 別名は Obsidian の `aliases` にも書く。別の呼び方で検索しても見つかる

### 8.4 入口のノート

- `本棚/はじめに.md`: 本棚の構成、探し方、書式の説明。**人とAIの両方に向けた案内**（スマホの AI にまずこれを読ませる）
- `本棚/目次/月別/2026-09.md`: その月の資料の一覧と、決定・未解決の抜き出し
- `本棚/目次/未解決.md`・`決定.md`: 日報の「未解決」「決定」をまたいで集めたもの（解決したら取り消し線）
- 今の `本棚/棚/`（日付別・出所別・話題別）は、上に置き換える

### 8.5 脳との行き来

- 大脳皮質の写し（v0.6 4.1）の各記憶から、出典の原文と話題のノートへリンクする
- 話題のノートから、その話題の記憶（写し）へリンクする
- 脳が忘れても、話題のノートと原文は残る。「脳は忘れたが、本棚を見ればわかる」を形にする

## 9. 確認待ち

- Jev の API キー（早期アクセスの待機リストへの登録はオーナーの操作が要る）。Kev で足りれば不要
- オーナーの MacBook Air は 24GB（2026-09-30）。Kev-4B・Jeff-2B は載る見込み（重さからの見積もり。実機で確かめる）
- Jev の日本語での精度（キーが来たら、評価質問セットと同じ資料で確かめる）
- 忘れるまでの期間と強さのしきい値
