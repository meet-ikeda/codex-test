## 1. 全体構成

```
┌──────────────── 自宅 PC ────────────────────────────────────────────┐
│                                                                    │
│  Claude Desktop ─┐                                                 │
│  Codex ──────────┼─(MCP / stdio)─→ exobrain-mcp ─┐                 │
│  claude -p（睡眠）┘   各アプリが起動する            │                 │
│                                                  ├─→ 脳 brain.db   │
│  ブラウザ ─(http://127.0.0.1)─→ exobrain app ────┘   （PC 内）      │
│   グラフ／メモ貼り付け／睡眠ボタン／消去             │                  │
│                      常駐: タイマー・受け取り箱の見張り・バックアップ   │
│                                                  │                 │
│  Google ドライブ同期フォルダ  ←──────────────────────┘                 │
│   exobrain/受け取り箱/   ← あなたがメモを置く                          │
│   exobrain/本棚/         ← 原文を保管（Obsidian でも開ける）          │
│   exobrain/バックアップ/ ← 脳のスナップショット                        │
└────────────────────────────────────────────────────────────────────┘
```

- **exobrain-mcp**: AI の入口。Claude Desktop や Codex が必要なときに起動します。
- **exobrain app**: PC にログインしたときに起動して常駐します。画面の表示、タイマー、受け取り箱の見張り、バックアップを担当します。
- どちらも同じ脳（SQLite）を使います。複数のプロセスから同時に使うため、WAL モードで開きます。

### 使う技術

| 部分 | 採用 | 理由 |
|---|---|---|
| 言語 | Python 3.10 以上 | 試作と同じ。標準ライブラリで SQLite と HTTP サーバーが使える |
| AI との接続 | MCP Python SDK 2.x（`mcp`） | この環境で 2.2.0 を実際に入れて動作を確認済み |
| 脳 | SQLite（WAL） | 追加のインストールが不要 |
| 本棚 | Markdown ファイル | 一度書いたら変更しないので同期フォルダに置いても安全。Obsidian でも読める |
| グラフ表示 | sigma.js と graphology | WebGL で描くので点が数千あっても動く（ https://www.pkgpulse.com/guides/cytoscape-vs-vis-network-vs-sigma-graph-visualization-2026 ）。ファイルを同梱し、インターネット接続なしで動かす |
| AI による睡眠 | Claude Code の非対話モード（`claude -p`）と `--mcp-config` | この環境の `claude --help` で、両方のオプションがあることを確認済み |

## 2. データ構造

### 2.1 本棚（Google ドライブ上のファイル）

```
exobrain/
  受け取り箱/                 あなたがメモを置く。取り込んだら空になる
  本棚/
    原文/2026/09/
      20260926-1432_claude_記憶アプリの要件定義.md
      20260926-2105_memo_採用サイトの気づき.md
    棚/                      棚の目録。睡眠のたびに作り直す
      日付別.md
      出所別.md
      話題_採用ブランディング.md    ← 原文へのリンクを並べる
  バックアップ/
```

原文ファイルの先頭には、次のような属性情報を付けます。

```yaml
---
id: src_01J...                # 識別子
kind: daily_report            # daily_report（AI 日報）または memo（あなたのメモ）
author: ai                    # ai または human
ai_name: Claude Desktop
created_at: 2026-09-26T14:32:00+09:00
sha256: 9f2c...               # 本文のハッシュ。改ざん検知に使う
---
（ここから下は受け取った原文そのまま）
```

- 原文ファイルは一度書いたら二度と書き換えません。
- 棚を移すときも原文ファイルは動かさず、目録（`棚/*.md`）の記載だけを変えます。

### 2.2 脳（PC 内の `~/.exobrain/brain.db`）

脳は「出来事の記録（イベント）」を正本にしています。要素やつながりの表は、イベントから計算した結果です。そのため、いつでも作り直せて（`exobrain rebuild`）、どの時点にも戻せます（要件 FR-08）。

```
events       追記のみ・ハッシュチェーン付き。あらゆる変更がここに残る
  id, at, actor(human|ai:<名前>|sleep), type, payload_json, content_sha256, prev_hash, hash
  ↓ 計算して作る
sources      原文の目録: id, path, kind, author, ai_name, created_at, sha256, erased
nodes        要素
  id, kind, label, body, source_id, source_span, created_by, created_at,
  base_strength, access_count, last_activated_at, status(active|superseded|dormant|erased)
edges        つながり
  src, dst, kind, weight(0〜1), co_activations, last_reinforced_at, origin(ai|human|sleep)
sessions     短期記憶: id, ai_name, started_at, last_seen_at, activated_node_ids
shelves      棚の割り当て: source_id, shelf, assigned_by, at
```

#### 要素の種類（`nodes.kind`）

| 種類 | 例 | 変えられるか |
|---|---|---|
| `episode`（エピソード記憶） | 「9/26 Claude と要件定義。いきなり実装して注意された」 | 変えられない |
| `semantic`（意味記憶） | 「本棚は Google ドライブに置く」 | 新しい版が古い版を置き換える（古い版は残る） |
| `procedural`（手続き記憶） | 「作る前に要件を確認する」「事実は検索して出典を示す」 | 同上 |
| `concept`（概念） | 「採用ブランディング」「Google ドライブ」 | つながりの中継点。Obsidian のタグに相当 |

#### つながりの種類（`edges.kind`）

`association`（連想）、`about`（〜についての要素）、`derived_from`（〜から導いた）、`supersedes`（新しい版）、`contradicts`（矛盾）、`part_of`（〜の一部）。

#### 消去しても改ざん検知が壊れない仕組み

イベントのハッシュは、本文そのものではなく**本文のハッシュ**（`content_sha256`）から計算します。消去するときは本文だけを消し、本文のハッシュは残します。こうすると、消去後もハッシュチェーンの検証が通ります。

## 3. 記銘（覚える）

### 3.1 AI 日報（FR-16）

AI は会話の区切りで `submit_daily_report` を呼びます。**日報の本文と、要素への分解を同じ AI が 1 回でまとめて送る**ので、分解のために別の AI を動かす費用はかかりません。

```jsonc
submit_daily_report({
  "ai_name": "Claude Desktop",
  "title": "記憶アプリの要件定義",
  "report": "（Markdown の日報本文。そのまま本棚へ）",
  "elements": [
    {"kind": "episode",    "text": "要件定義を飛ばして実装し、注意された", "concepts": ["exobrain", "進め方"]},
    {"kind": "procedural", "text": "作る前に要件を確認する", "concepts": ["進め方"], "importance": 0.9},
    {"kind": "semantic",   "text": "Claude は Pro プラン", "concepts": ["Claude", "契約"]}
  ],
  "used_memory_ids": ["n_123", "n_456"]   // この会話で実際に役立った記憶
})
```

サーバー側の処理:
1. 原文を本棚に保存する
2. 要素を作る。概念は既存のものと突き合わせ、なければ作る
3. 同じ日報から生まれた要素どうしをつなぐ
4. `used_memory_ids` のつながりを強める

要素の形式はサーバー側で検証します。本文が長すぎる、種類が不正、といった場合は、理由を添えて AI に返し、送り直してもらいます。

### 3.2 あなたのメモ（FR-15）

- 受け取り箱に置いたファイル、または画面に貼り付けたメモは、まず原文のまま本棚に保存します。受け取り箱にファイルが残るのは、取り込みが終わるまでの間だけです。
- 要素への分解は、次の睡眠で AI が行います（あなたのメモから AI の考えで要素を作るため、`author` は human、要素の `created_by` は `sleep` になります）。

### 3.3 会話中の記憶（`remember`）

日報を待たずに残したいことがあれば、AI は会話の途中でも `remember` で要素を追加できます。

## 4. 想起（思い出す）: 活性化拡散

### 4.1 手順

```
手がかり（会話の話題など）
   │ ① 種を見つける: 概念や要素の見出しと照合（日本語は 2 文字ずつ区切って比べる）
   ▼       ＋ この会話で最近思い出した要素（短期記憶）
種の要素に活性値 1.0
   │ ② 広げる: 最大 3 段まで
   │    隣の活性値 += 自分の活性値 × つながりの強さ × 0.5（1 段ごとに半減）÷ √(つながりの数)
   │    √ で割るのは、何にでもつながる概念が全体を支配しないようにするため（ファン効果）
   ▼
各要素の活性値 × 基礎の強さ（最近・よく使われたものほど高い）
   │ ③ 詰める: 活性値の高い順に、トークンの上限（設計値 1,500）に収まるまで入れる
   │    手続き記憶（あなたへの接し方のルール）は、上限の 30% を優先的に確保する
   ▼
④ ひらめき枠: 2 段以上離れていて、手がかりと直接一致せず、主な答えとは別のまとまりに
   属する要素から 1〜3 件。どのつながりを経て届いたかを添える
   ▼
⑤ 一緒に思い出された要素どうしのつながりを少し強める（ヘッブ則）
```

### 4.2 AI に返す形（例）

```
## あなたについて（手続き記憶）
- 作る前に要件を確認する [n_88]
- 事実は検索し、出典を示す [n_12]
## 関連する記憶
- [意味] 本棚は Google ドライブに置く（9/26, Claude）[n_140]
- [出来事] 9/26 要件定義でいきなり実装して注意された [n_131]
## ひらめき（遠い連想）
- [意味] 採用サイトでは「原文を残す」ことが信頼につながると話していた [n_52]
  経路: exobrain → 原文保管 → 採用サイトの信頼設計
```

各行の `[n_…]` は要素の識別子です。AI は日報の `used_memory_ids` でこれを報告し、つながりの強化に使われます。

### 4.3 トークン量の数え方

正確なトークン数は AI ごとに異なるため、文字数から控えめに見積もります（日本語は 1 文字を 1 トークン、英数字は 4 文字を 1 トークンと数える。設計値）。

## 5. 睡眠

### 5.1 始め方（FR-22）

| 起動のしかた | しくみ |
|---|---|
| 睡眠ボタン | 画面のボタンを押すと、段階 A と段階 B を続けて実行する |
| タイマー | 常駐アプリが設定時刻に実行する（既定ではオフ） |
| PC 起動時 | 常駐アプリの起動時に、前回の睡眠から 20 時間以上（設計値）たっていれば実行する |

### 5.2 段階 A: 機械的な整理（AI なし・費用なし）

1. 受け取り箱のファイルを本棚へ取り込む
2. **再生**: 前回の睡眠以降の出来事を思い出し直し、一緒に使われた要素のつながりを強める
3. **減衰**: 長く使われていないつながりを弱める（半減期 30 日。設計値）。一定より弱くなった要素は「眠っている」状態にして想起の対象から外す。消しはしない
4. **新しい結びつきの候補**: 共通の概念を 2 つ以上持つのに直接つながっていない要素どうしを、弱いつながりで結ぶ（`origin=sleep`）
5. **重複・矛盾の候補**を段階 B に回す

### 5.3 段階 B: AI による整理

`claude -p` で Claude を起動し、exobrain の睡眠用の道具だけを使わせます。

```
claude -p "exobrain の睡眠を実行してください" \
  --mcp-config <exobrain 用の設定> \
  --allowedTools <睡眠用の道具だけ>
```

Claude は `sleep_next_batch` で作業を 1 束受け取り、処理して `sleep_apply` で返す、を繰り返します。

| 作業 | 内容 |
|---|---|
| 分解 | まだ要素にしていないメモを要素に分ける |
| 統合 | 似た出来事がいくつもあれば、意味記憶・手続き記憶にまとめる（例: 「結論を先に」と 3 回言われた → 手続き記憶にする） |
| 矛盾の解消 | 食い違う意味記憶があれば、新しいほうの版を作る。古い版は残し、`supersedes` でつなぐ |
| つながり | 段階 A の候補を確かめる。意味のあるものは強め、無関係なものは外す |
| 棚の整理 | 原文を話題の棚に割り当てる |

- 1 回の睡眠で処理する束の数に上限を設けます（設計値 20 束）。Claude の利用枠を使いすぎないためです。
- 最後に `sleep_finish` で「夢日記」を書きます。何を思い出し、何をまとめ、どのつながりが変わったかを記録し、本棚の `夢日記/` に置きます。
- Claude Code が見つからない環境では、段階 A だけを実行します。段階 B は「未実行」として夢日記に残し、次の睡眠で処理します。

## 6. 指摘による書き換え（FR-23）

### 6.1 流れ

```
間違いを指摘される／AI が自分で気づく
   │ AI が trace_correction(指摘の内容, いまの文脈, 使ってしまった記憶) を呼ぶ
   ▼
① 記憶をたどる（活性化拡散。手続き記憶・意味記憶・過去の指摘の出来事を中心に）
   ├─ 見つかった ──→ ② つながりの改善（reinforce）
   │                   ・その記憶と、いまの文脈の概念とのつながりを強める
   │                     （記憶はあったのに今回思い出せなかった＝つながりが弱かった、とみなす）
   │                   ・記憶の基礎の強さを上げる。同じ指摘が 3 回（設計値）を超えたら、
   │                     想起のたびに必ず入れる「常駐ルール」に格上げする
   │                   ・間違った記憶を使っていた場合は、文脈とのつながりを弱める。
   │                     事実が誤っていたら新しい版を作る（古い版は残す）
   │
   └─ 見つからない → ③ 本棚の原文を全文検索
                        ├─ 見つかった ──→ ④ 原文の該当箇所から要素を作り、脳に追加（restore）
                        │                   原文の箇所を指し、いまの文脈とつなぐ
                        └─ 見つからない → ⑤「過去の記憶にも本棚にもありません」と AI に返す（new）
                                            AI はそのまま利用者に伝え、指摘を新しい記憶として残す
   ▼
どの場合も、「指摘を受けた」という出来事（エピソード記憶）を 1 件残す
```

### 6.2 道具を 2 つに分ける理由

- `trace_correction` は探すだけで、脳は変えません。脳と本棚それぞれの候補を返します。
- 候補が本当に同じ指摘かどうかは、文脈がわかっている AI が判断し、`apply_correction` で書き換えます。
- サーバーは手順を強制します。
  - 脳の候補がないのに「つながりの改善」はできません。
  - 本棚の候補がないのに「原文から追加」はできません。
  - どちらもない場合、返答に「過去の記憶にも本棚にもありません」という利用者向けの文言を必ず含めます。

### 6.3 本棚の全文検索

- 原文を SQLite FTS5 の trigram 方式で索引化します。日本語でも単語の区切りなしで検索できます（SQLite 3.34.0 で追加された機能。 https://sqlite.org/releaselog/3_34_0.html ）。
- この環境で、日本語の検索が動くことを試して確認済みです。
- 3 文字未満の語は、通常の部分一致検索で補います（設計上の判断）。
- 索引は脳（PC 内）に置き、原文ファイルは変更しません。

## 7. AI に渡す道具（MCP）

| 道具 | 使う場面 | 書き込み |
|---|---|---|
| `start_session(ai_name)` | 会話の始め。短期記憶を開き、あなたの基本情報（手続き記憶が中心）を上限 500 トークン（設計値）で返す | 短期記憶のみ |
| `recall(cue, session_id)` | 話題が変わったとき | つながりの強化のみ |
| `remember(elements, session_id)` | 会話中に残したいことがあるとき | 要素の追加 |
| `submit_daily_report(...)` | 会話の区切り | 原文と要素の追加 |
| `open_source(source_id)` | 原文を読みたいとき | なし |
| `trace_correction(correction, context, used_memory_ids)` | 間違いを指摘されたとき、自分で気づいたとき | なし（探すだけ） |
| `apply_correction(mode, ...)` | trace の結果を受けて。mode は reinforce / restore / new | つながりの強化・弱化、要素の追加、指摘の出来事 |
| `sleep_next_batch` / `sleep_apply` / `sleep_finish` | 睡眠中のみ（睡眠用の設定でだけ公開する） | 統合結果の追加 |

**AI に渡さないもの**: 消去、原文の変更、エピソード記憶の変更、一時停止の解除。

MCP サーバーの `instructions` には、次の方針を書いておきます。
- 会話の始めに `start_session` を呼ぶ
- 話題が変わったら `recall` を呼ぶ
- 区切りで `submit_daily_report` を呼ぶ
- 間違いを指摘されたら、言い訳より先に `trace_correction` を呼ぶ
- human が書いた記憶を優先する

実際に各 AI が従うかは、第 1 段階で確かめます（要件 11 章のリスク）。

## 8. 画面（`http://127.0.0.1:<ポート>`）

| 画面 | 内容 |
|---|---|
| グラフ | 記憶の網を表示する。色は記憶の種類、線の太さはつながりの強さ、点の大きさは基礎の強さ。点を選ぶと内容・出所・原文を表示する。検索、種類・期間・出所での絞り込み、前回の睡眠で変わった箇所の強調表示、眠っている要素の表示切り替えができる |
| 本棚 | 棚ごとに原文を一覧・閲覧する |
| メモ | 貼り付けて渡す |
| 睡眠 | 睡眠ボタン、タイマーの設定、夢日記の一覧 |
| 安全装置 | 消去、AI からの書き込みの一時停止、改ざんの検証、バックアップと復元 |

画面は自分の PC からしか開けないようにします（`127.0.0.1` だけで待ち受ける）。

## 9. 安全装置

### 9.1 消去（FR-09）

- 対象を選べます。原文 1 件（そこから生まれた要素もまとめて消す）、要素 1 件、期間でまとめて、のいずれかです。
- 消去を実行すると、次の順で処理します。
  1. 本棚の原文ファイルを削除する
  2. 該当する要素の本文とイベントの本文を消し、本文のハッシュと「消去済み」の印だけを残す
  3. 古いバックアップをすべて削除し、新しいバックアップを 1 つ作る
- 誤操作を防ぐため、消去する件数を表示し、確認の語句を入力しないと実行できないようにします。
- **確認できなかった点:** Google ドライブで削除したファイルがゴミ箱にどれだけの期間残るかは確認できていません。消去後には「Google ドライブのゴミ箱も空にしてください」と案内を表示します。

### 9.2 一時停止（FR-10）

画面のスイッチで、AI からの書き込み（記銘・日報）を止められます。止めている間は、AI に「一時停止中です」と返します。思い出すことはできます。

### 9.3 バックアップ

- 睡眠のたびに、脳のスナップショットをバックアップフォルダに書き出します。SQLite のバックアップ機能を使い、使用中のファイルを直接コピーすることはしません。
- 保存するのは直近 7 世代です（設計値）。
