# 日報の書き方ルール（案）

**状態:** 実装済み（2026-10-05）。毎晩の自動日報・`/日報`・Gemini の Gem の指示に組み込み、案件ノートは睡眠のたびに作り直す。AI は案件の話を始めたら `open_project` で案件ノートを読む。
**対象:** 毎晩の自動日報（Codex・Claude Code・Cowork）、`/日報`、`/預けて`、ChatGPT・Gemini のダウンロード。
**書式の土台:** Obsidian の書き方（kepano/obsidian-skills の obsidian-markdown。プロパティ・`[[リンク]]`・コールアウト）。

---

## 1. 1 枚の単位

- **1 つの案件 × 1 日 = 1 枚。** 同じ案件・同じ日の会話は、AI やスレッドが違っても 1 枚にまとめる。すでにあれば書き足す
- 案件のない話（雑談・道具の設定など）は「案件: なし」とし、スレッドごとに 1 枚

## 2. 先頭（プロパティ）

```yaml
---
種類: 日報
案件: "[[案件名]]"
日付: 2026-10-04
書き手: [Codex, Claude Code]
元の会話: ["[[会話抜粋 2026-10-04 …]]"]
tags: [日報]
---
```

## 3. 見出し（この順番。名前を変えない）

| 見出し | 書くこと |
|---|---|
| `## 今の状況` | この日の終わりに、案件がどこまで進んだか（2〜3 行）。案件ノートの「今の状況」になる |
| `## 決まったこと` | 1 行 1 件。理由をオーナーが言っていれば「理由:」で続ける |
| `## ボツになったこと` | ボツになった案と、その理由 |
| `## 前提・条件` | 新しく分かった・変わった条件（使ってよい言葉、出さない名前、相手、締め切りなど） |
| `## オーナーの言葉` | 理由やこだわりを言った発言だけを、言い換えずに `> ` で |
| `## あったこと` | 流れ。反応（「もう、言葉もないです」など）はここに書く |
| `## 次にやること` | 残っていること |

## 4. 書き方の決まり

1. **理由は、オーナーが言ったときだけ書く。** 推測で埋めない。AI の考えは、オーナーの考えと混ぜずに分ける:
   ```
   > [!note] AI の解釈
   > 例に挙がった言葉は、どれも動詞として定着しているので、名詞より動詞がよいと考えた
   ```
2. **反応は理由ではない。** 「言ったはずです」「もう、言葉もないです」は「あったこと」に書き、「オーナーの言葉」には入れない
3. 案件・人・会社・道具は、初めて出るところで `[[名前]]` にする（別の呼び方は `[[名前|呼び方]]`）
4. 前の日報と同じ決まりは、くり返さない（変わったときだけ書く）
5. 案の全文は書かない。案の名前と結果だけ（全文は元の会話にある）
6. アプリの指示文や案件データ（JSON など）は、元の会話の抜粋に入れない

## 5. 案件ノート（同じ案件をつなぐ）

`本棚/案件/<案件名>.md` を、毎晩の睡眠で書き直す。日報が正本で、案件ノートはそのまとめ（手で直しても次の睡眠で書き直される）。

```
# [[案件名]]

## 今の状況        ← いちばん新しい日報の「今の状況」
## 前提・条件      ← 全部の日報から。変わったものは ~~打ち消し線~~ で残す
## 決まったこと    ← 新しい順。理由と、どの日報かへのリンク
## ボツになったこと ← 案と理由
## 次にやること
## 日報            ← この案件の日報へのリンク（新しい順）
```

AI が案件の話を始めたら、まずこのノートを読む。
